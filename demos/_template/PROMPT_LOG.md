PROMPT_LOG.md
GitHub Copilot Chat에 입력한 프롬프트를 시간 순서대로 기록합니다.

왜? 좋은 프롬프트의 감각은 시행착오를 봐야 늡니다.
코드를 베끼는 게 아니라 프롬프트를 배우는 과정입니다.

#1 — 프로젝트 초기 골격
Prompt
Streamlit으로 "우리반 마음 지도 : 또래관계 네트워크 시각화 도구"를 만들 거야. 사용자는 초등학교 담임교사이고 파이썬 지식이 없어. 기본 골격만 만들어줄 수 있어?

결과: 페이지 설정 + 제목/캡션 3줄. 깔끔함. ✅

#2 — CSV 구조 정의 및 검증 함수
Prompt
이 도구는 22명 학생의 교우관계 데이터를 입력받아. CSV 컬럼은 5개: name (학생 이름), best_friend (가장 친한 친구 이름), distant_friend (서먹한 친구 이름), reason_pos (친함 이유), reason_neg (서먹함 이유).

검증 함수 validate_csv(df)를 만들어줘. 다음을 확인해:

필수 컬럼 5개 모두 있는지

정확히 22행인지 (학생 수)

모든 필드에 빈 값(NaN, 공백)이 없는지

에러가 있으면 에러 메시지를 반환하고, st.error()로 보여준 후 st.stop()해줘.

결과: 명세에 맞는 견고한 입력 검증. 사용자 실수를 사전 차단. ✅

교훈: 단순히 "CSV 업로드" 대신 "22행, 5개 컬럼, 모두 필수" 같은 도메인 맥락을 주면 검증이 정확해진다.

#3 — 사이드바 CSV 업로더 + 메트릭 카드
Prompt
사이드바에 st.file_uploader로 CSV 업로드 위젯을 만들어줘. 업로드되면 한글(UTF-8, CP949, EUC-KR) 인코딩을 자동으로 감지하는 헬퍼 함수 read_csv_any()를 먼저 만들어줘.

업로드 전에는 "👈 왼쪽 사이드바에서 CSV 파일을 업로드하세요" 안내 메시지만 보이게 해줘.

업로드되면 상단에 st.columns(3)으로 3개의 메트릭을 띄워줘:

📋 총 응답자 (행 수)

👥 응답 완료 (빈 값 없는 행 수)

⚡ 완성도 (%)

그 아래로 st.dataframe으로 표 전체를 보여줘.

결과: 깔끔한 UX. 교사는 즉시 응답 상황을 파악 가능. ✅

교훈: 엑셀 CSV는 기본 CP949 → 다중 인코딩 시도가 필수. "한글이 깨져"보다 "교사가 엑셀에서 저장했을 때 보통 CP949" 라고 맥락을 주면 코드가 견고해진다.

#4 — 네트워크 그래프 시각화
Prompt
NetworkX로 학생 관계도를 DiGraph로 만들어줘. 다음 두 함수를 구현해:

build_network_graph(df):

모든 학생을 노드로 추가

best_friend 엣지는 초록색 (color="green")

distant_friend 엣지는 빨간색 (color="red")

화살표 방향: 자신 → 대상 친구

visualize_network(G):

Plotly로 인터랙티브 그래프 생성

Spring layout으로 노드 자동 배치

범례: "🟢 초록 화살표 = 친한 친구", "🔴 빨간 화살표 = 서먹한 친구"

제목: "또래관계 네트워크 (화살표 방향: 자신 → 대상)"

matplotlib 말고 Plotly를 써줘. 한글이 자동으로 잘 나와.

결과: 관계도가 한눈에 들어옴. 친밀/소외 관계를 색으로 직관적 구분. ✅

교훈: Streamlit Cloud는 matplotlib 한글 폰트 미설치 → Plotly가 SVG 렌더링이라 한글 문제 없음. 도구 선택 시 배포 환경을 고려해야 한다.

#5 — 사회네트워크 분석 지표
Prompt
calculate_network_metrics(df, G) 함수를 만들어줘. 각 학생마다 다음 7개 지표를 계산하고 DataFrame으로 반환해:

👍 받은 친밀표시: 다른 학생들이 이 학생을 best_friend로 선택한 횟수

👎 받은 소외표시: 다른 학생들이 이 학생을 distant_friend로 선택한 횟수

🔗 중심성: NetworkX degree_centrality (0~1, 높을수록 사교성 높음)

💚 선택한 친한친구: 이 학생이 best_friend로 선택한 수

💔 선택한 소외친구: 이 학생이 distant_friend로 선택한 수

📊 관계성향: "받은 친밀표시 > 받은 소외표시"면 "외향적", 반대면 "내향적"

결과는 "👍 받은 친밀표시" 내림차순으로 정렬해줘.

그리고 화면에는:

📖 st.expander로 지표 설명 축약 가능하게

📊 전체 지표 표

🏆 친밀도 상위 5명

⚠️ 소외도 상위 5명

결과: 각 학생의 사회네트워크 위치를 정량적으로 파악 가능. 교사가 소외 위험군을 식별. ✅

교훈: 명세 범위를 넘어, 교사 입장에서 "어떤 학생을 주목해야 할까?"에 답할 수 있도록 설계했다. → 도구가 산다.

#6 — 노드 크기를 선택 받은 횟수로 표현
Prompt

결과: 노드 크기가 "받은 선택의 총 개수"에 따라 동적으로 조절됨. ✅

구현:

호버 정보에 "선택 받음: N명" 추가

교훈: - 구체적인 산업 용어 대신 직관적 설명 사용이 중요 ("in-degree"가 아니라 "많은 선택을 받은" 이라고 표현)

시각적 변수를 추가하면 데이터가 더 잘 읽힌다 (크기 = 선택도)

#7 — [트러블슈팅] 환경적 요인으로 인한 SyntaxError 해결
Prompt
if df[col].isna().any() 또는 (df[col] == "").any():
SyntaxError: invalid syntax 에러가 발생해. 코드를 복사해서 붙여넣어도 자꾸 파이썬 코드 안에 한글 '또는', '및'이 들어가거나 st.success가 st.성공으로 멋대로 바뀌어. 어떻게 막아야 해?

결과: 파이썬이나 Streamlit의 오류가 아닌, OS/환경(Mac 맞춤법 자동 수정 또는 한컴 입력기 등)의 '텍스트 자동 대치' 기능 오작동임을 발견하고 우회 및 해결. 🛠️

해결 및 우회법:

OS 시스템 설정에서 '맞춤법 자동 수정' 기능 일시 비활성화

에디터에서 강제 변환이 일어난 직후 곧바로 Ctrl + Z / Cmd + Z (실행 취소) 를 눌러 영문 원본(or, and, success)으로 롤백시키는 요령 터득

마우스 드래그 복사-붙여넣기(Ctrl + C/V)를 활용해 자동 변환 엔진이 개입할 여지를 원천 차단

교훈: 코딩 중 발생하는 모든 에러가 소스코드 자체의 논리 오류는 아니다. 개발 환경, 운영체제(OS)의 입력기 설정 등 외부적 요인이 코드를 오염시킬 수 있음을 인지하고 다각도로 접근해야 한다.

#8 — 주관식 사유 추출 방식 고도화 (단어 쪼개기 ➔ 의미별 문장 그룹화)
Prompt
단어를 쪼개서 빈도를 뽑아내는 기존 방식은 결과가 파편화되어 나와서 이상해. 차라리 이전 화면의 레이아웃이나 지표 설명은 그대로 유지하되, 주관식 이유를 비슷한 것끼리 묶어서 분석해 줘. 예를 들어 "성격이 좋다"와 "성격이 활발하다"를 하나의 의미군으로 묶어서 문장 형태로 요약해 표현하는 식으로 변경해 줘.

결과: 파편화된 단어 나열 방식에서 벗어나, 교사가 학급 경영에 즉각 참고할 수 있는 '유사 의미군 기반의 문장형 그룹 요약' 기능으로 고도화 성공. 🎉

구현:

기존의 extract_keywords 단어 빈도 함수 제거

규칙 기반 핵심 패턴 감지 알고리즘(summarize_reasons_by_group) 도입

친밀 사유: 성격/활발(성격이 좋고 활발함), 친절/배려(친절하고 배려심이 많음), 재미/유머 등

서먹한 사유: 말/소통부족(평소 대화나 소통이 부족함), 싸움/갈등, 성격차이 등

분류된 그룹별로 인원수를 합산하여 성격이 좋고 활발함(3명) / 취미나 대화가 잘 통함(1명) 형태로 조립하여 최종 데이터프레임에 깔끔하게 반영

교훈: 사용자의 불만족("좀 이상해") 포인트를 명확히 짚어 대안을 제시해야 한다. 텍스트 마이닝 시 단순 빈도 분석보다 도메인에 특화된 의미론적 그룹화(Clustering/Mapping)가 실무 관점에서 훨씬 더 가치 있는 정보를 제공한다.

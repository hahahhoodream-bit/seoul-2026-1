# PROMPT_LOG.md

GitHub Copilot Chat에 입력한 프롬프트를 시간 순서대로 기록합니다.

> **왜?** 좋은 프롬프트의 감각은 시행착오를 봐야 늡니다.
> 코드를 베끼는 게 아니라 프롬프트를 배우는 과정입니다.

> **Prompt**

## #2 — CSV 구조 정의 및 검증 함수

> **Prompt**
> 이 도구는 22명 학생의 교우관계 데이터를 입력받아. CSV 컬럼은 5개: `name` (학생 이름), `best_friend` (가장 친한 친구 이름), `distant_friend` (서먹한 친구 이름), `reason_pos` (친함 이유), `reason_neg` (서먹함 이유).
> 
> 검증 함수 `validate_csv(df)`를 만들어줘. 다음을 확인해:
> - 필수 컬럼 5개 모두 있는지
> - 정확히 22행인지 (학생 수)
> - 모든 필드에 빈 값(NaN, 공백)이 없는지
> 
> 에러가 있으면 에러 메시지를 반환하고, `st.error()`로 보여준 후 `st.stop()`해줘.

**결과:** 명세에 맞는 견고한 입력 검증. 사용자 실수를 사전 차단. ✅

**교훈:** 단순히 "CSV 업로드" 대신 **"22행, 5개 컬럼, 모두 필수"** 같은 도메인 맥락을 주면 검증이 정확해진다.

## #3 — 사이드바 CSV 업로더 + 메트릭 카드

> **Prompt**
> 사이드바에 `st.file_uploader`로 CSV 업로드 위젯을 만들어줘. 업로드되면 한글(UTF-8, CP949, EUC-KR) 인코딩을 자동으로 감지하는 헬퍼 함수 `read_csv_any()`를 먼저 만들어줘.
> 
> 업로드 전에는 "👈 왼쪽 사이드바에서 CSV 파일을 업로드하세요" 안내 메시지만 보이게 해줘.
> 
> 업로드되면 상단에 `st.columns(3)`으로 3개의 메트릭을 띄워줘:
> - 📋 총 응답자 (행 수)
> - 👥 응답 완료 (빈 값 없는 행 수)
> - ⚡ 완성도 (%)
>
> 그 아래로 `st.dataframe`으로 표 전체를 보여줘.

**결과:** 깔끔한 UX. 교사는 즉시 응답 상황을 파악 가능. ✅

**교훈:** 엑셀 CSV는 기본 CP949 → 다중 인코딩 시도가 필수. "한글이 깨져"보다 **"교사가 엑셀에서 저장했을 때 보통 CP949"** 라고 맥락을 주면 코드가 견고해진다.

## #4 — 네트워크 그래프 시각화

> **Prompt**
> NetworkX로 학생 관계도를 `DiGraph`로 만들어줘. 다음 두 함수를 구현해:
>
> 1. `build_network_graph(df)`: 
>    - 모든 학생을 노드로 추가
>    - `best_friend` 엣지는 **초록색** (`color="green"`)
>    - `distant_friend` 엣지는 **빨간색** (`color="red"`)
>    - 화살표 방향: 자신 → 대상 친구
>
> 2. `visualize_network(G)`:
>    - Plotly로 인터랙티브 그래프 생성
>    - Spring layout으로 노드 자동 배치
>    - 범례: "🟢 초록 화살표 = 친한 친구", "🔴 빨간 화살표 = 서먹한 친구"
>    - 제목: "또래관계 네트워크 (화살표 방향: 자신 → 대상)"
>
> matplotlib 말고 **Plotly를 써줘. 한글이 자동으로 잘 나와.**

**결과:** 관계도가 한눈에 들어옴. 친밀/소외 관계를 색으로 직관적 구분. ✅

**교훈:** Streamlit Cloud는 matplotlib 한글 폰트 미설치 → Plotly가 SVG 렌더링이라 한글 문제 없음. **도구 선택 시 배포 환경을 고려해야 한다.**

## #5 — 사회네트워크 분석 지표

> **Prompt**
> `calculate_network_metrics(df, G)` 함수를 만들어줘. 각 학생마다 다음 7개 지표를 계산하고 DataFrame으로 반환해:
>
> - **👍 받은 친밀표시**: 다른 학생들이 이 학생을 `best_friend`로 선택한 횟수
> - **👎 받은 소외표시**: 다른 학생들이 이 학생을 `distant_friend`로 선택한 횟수
> - **🔗 중심성**: NetworkX `degree_centrality` (0~1, 높을수록 사교성 높음)
> - **💚 선택한 친한친구**: 이 학생이 `best_friend`로 선택한 수
> - **💔 선택한 소외친구**: 이 학생이 `distant_friend`로 선택한 수
> - **📊 관계성향**: "받은 친밀표시 > 받은 소외표시"면 "외향적", 반대면 "내향적"
> - 결과는 "👍 받은 친밀표시" 내림차순으로 정렬해줘.
>
> 그리고 화면에는:
> - 📖 `st.expander`로 지표 설명 축약 가능하게
> - 📊 전체 지표 표
> - 🏆 친밀도 상위 5명
> - ⚠️ 소외도 상위 5명

**결과:** 각 학생의 사회네트워크 위치를 정량적으로 파악 가능. 교사가 소외 위험군을 식별. ✅

**교훈:** **명세 범위를 넘어, 교사 입장에서 "어떤 학생을 주목해야 할까?"에 답할 수 있도록 설계했다.** → 도구가 산다.

## #6 — 노드 크기를 선택 받은 횟수로 표현

> **Prompt**
> 지금 네트워크 그래프 시각화에서 모든 노드가 같은 크기여서 아쉬워. 그 많은 선택을 받은 아이들의 이름을 친한 친구든 서먹한 친구든 좀 크게 나타나고 적은 선택을 받은 친구는 크기가 작게 나타나도록 도식화 할 수 있어? 선은 그대로 나타내고.

**결과:** 노드 크기가 "받은 선택의 총 개수"에 따라 동적으로 조절됨. ✅

**구현:**
1. `visualize_network(G, df)` 함수에 `df` 파라미터 추가
2. 각 학생의 **in-degree** 계산 (친밀 + 소외 선택 합계)
3. 노드 크기를 **15px ~ 50px** 범위로 정규화
4. 호버 정보에 `"선택 받음: N명"` 추가

**교훈:** 
- **구체적인 산업 용어 대신 직관적 설명 사용**이 중요 ("in-degree"가 아니라 "많은 선택을 받은" 이라고 표현)
- **시각적 변수를 추가**하면 데이터가 더 잘 읽힌다 (크기 = 선택도)
- **호버 정보 개선**으로 상호작용성 ↑
